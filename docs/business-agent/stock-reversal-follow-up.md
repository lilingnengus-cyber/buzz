# 履约逆转接入前的核对记录

本记录是后续实现清单，不表示功能已经实现或验收。当前订单取消发布与这些变化分开。

## 复用边界

固定三类操作：出库逆转、收货逆转、期初库存逆转。复用 Core 现有 reverse_shipment、reverse_receipt、reverse_opening 业务事务；为助手增加不可变操作意图、用户原因、完整签名确认和当前版本绑定。确认工具不接收模型重新提供的数量或成本。

现有 stock::authority_row / check_stock_scope 可提供单据法人、业务单元、往来方和仓库权限检查。仍需逐行核对品牌等数据范围，不能以单据头权限代替全部明细授权。

## 从当前事务发现的检查点

- 出库逆转恢复原出库数量、成本和库存预留，逆转对应应收；已核销应收会阻止执行。预览须展示恢复数量、恢复预留和往来影响，核对退货、原订单剩余量取消及之后业务对结果的影响。
- 收货逆转扣减原收货数量与成本并逆转应付；已核销应付或后续库存流水会阻止执行。当前应用检查扣减后数量/金额非负，数据库还通过约束保护“预留量＋隔离量不得超过现存量”。应把这类约束提前转成可读的业务阻塞原因，不能向用户承诺可执行再返回数据库错误。
- 期初逆转检查后续流水及预留量。预览与应用检查还需明确隔离量约束；数据库约束已经存在。
- 收货和期初目前查询后续流水后才锁库存余额。并发验收应让另一事务先持有余额锁、写入后续流水，再释放锁，验证逆转在获得锁后重新检查当前状态。不能只用确认前的一次读取作为最终事务依据。
- 原来源版本不能代表关联余额、订单、往来及退货状态。影响快照需覆盖真正决定结果的关联状态；最终事务内还需重新校验，解决预览至执行之间的变动。
- 保留旧浏览器调用及其幂等摘要兼容；助手原因随实际业务事务写入审计，不能只存在准备意图里。

## 后续验收

隔离数据库分别证明正常逆转、已核销拒绝、后续流水拒绝、预留/隔离量冲突、来源或关联状态变更、并发锁等待、越权、重复确认、幂等、原因审计和库存/成本/往来回读。补齐来源单据查找、当前版本和真实详情链接后，再发布固定工具。生产业务写入实测需要具体记录授权。
