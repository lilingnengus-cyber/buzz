# 企业助手完整业务流程覆盖

目标：企业助手写入覆盖完整业务流程。首批履约上线不能作为目标完成证据。

以 Business Core README 明确的 B1/B2/B3/B4/S1 业务边界及当前业务 API 为实现基线：销售、采购、库存、经营应收应付、真实利润与管理报表；银行连接、财务总账、法定报表当前不是 Core 已实现能力。业务记录中的付款确认不得宣称发起了银行转账。

## 覆盖与剩余工作

| 环节 | 当前证据 | 待完成 |
|---|---|---|
| 基础资料 | 按名称查找已上线 | 客户、供应商、商品/SKU、仓库及相关基础资料的创建、修改、停用，当前版本与范围检查 |
| 售前 CRM | 浏览器创建、修改、跟进已上线 | 助手录入商机、更新阶段和新增跟进，目标查找、字段补问与详情链接 |
| 销售订单 | 助手创建、修改草稿、预览及签名确认已上线 | 取消、剩余数量取消、暂停/恢复及明确原因的版本绑定 |
| 采购订单 | 助手创建、修改草稿、预览及签名确认已上线 | 剩余量取消、采购申请及补货到采购的转换 |
| 库存履约 | 期初、出库、收货草稿及签名确认已上线 | 出入库逆转、期初逆转，盘点录入/差异过账，以及来源明细查找 |
| 客户收款 | 草稿工具已有；收款记录确认本地实现并通过 Core 隔离闭环 | 部署确认链路；应收选择、核销预览、签名核销、核销逆转及收款逆转 |
| 供应商付款 | 草稿工具已有；付款记录确认本地实现并通过 Core 隔离闭环 | 部署确认链路；应付选择、核销预览、签名核销、核销逆转及付款逆转 |
| 退货 | Core 已有销售/采购退货与处置能力 | 助手创建、修改、确认、逆转，数量/成本/库存/往来影响及处置 |
| 履约细节 | Core 已有交付/到货等操作 | 将现有运输、交付状态等业务写入接入受控工具 |
| 经营费用/利润 | 助手可读利润及证据 | 费用调整草稿、修改、确认、分摊和逆转 |
| 管理报表 | 助手可读报表与快照 | 创建不可变管理报表快照及现有报表写入操作 |
| 异常与行动 | 分析/建议/待办可读，浏览器操作已有 | 明确授权创建待办与审批草稿、事件认领和状态流转；不把建议直接视为完成 |

权限管理与审批策略配置仍通过独立管理员授权路径，不允许业务助手自行提权。所有未覆盖的业务操作仍计为未完成，不因清单完成或某阶段测试通过而宣告整体目标完成。

## 逐项完成证据

每个写入需同时证明：固定工具与严格输入；当前用户能力和数据范围；名称/编号定位及缺字段补问；读取当前版本；影响真实状态的操作有服务端预览和签名确认；参数与确认绑定；既有业务事务执行；幂等、版本冲突、撤权、错误及审计；结果回读和对应详情链接。通过隔离环境实际闭环验证后再部署，真实业务写入测试仍需具体记录授权。

核销、退货等带金额/明细的确认不能仅绑定单据 ID。下一阶段需要服务端保存确定的操作意图，将全部目标、数量、金额和版本纳入摘要，确认工具从绑定意图取值，不能让模型在确认时另传金额或目标。

## 2026-09-19 收付款确认开发证据

新增两组 `get_customer_receipt_approval_preview` / `approve_customer_receipt`、`get_supplier_payment_approval_preview` / `approve_supplier_payment`，当前共 52 个固定工具。确认只改变业务收付款记录至 confirmed，待核销金额等于已核实金额，不改变应收应付核销额，不发起银行交易。

Core 隔离测试覆盖两类记录：精确金额字符串、确认影响、缺审批策略拒绝、撤销往来方范围后读取及执行均拒绝、失效摘要拒绝、成功确认和重复确认拒绝。Gateway/Read API/MCP 单元及 Host 定向测试、严格 Clippy、运行时工具集合探针分别作为分层证据。迁移 0036 不自动授予权限或创建策略；本批未部署，生产仍为上一批 48 工具配套服务。
