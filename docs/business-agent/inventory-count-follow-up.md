# 库存盘点助手接入

## 当前业务行为

`InventoryCountService::create` 直接创建 counting 状态并保存库存快照。数据库触发器在 counting/counted 期间阻止该法人、仓库和 SKU 的库存流水与余额更新，因此它会影响实际履约，不能作为无副作用的普通草稿工具。submit 录入全部实盘行并转为 counted；post 写差异流水、库存余额、盘点事件及审计并释放冻结；cancel 释放未过账盘点的冻结。

完整接入需包含范围与逐行库存查询、准备/确认冻结盘点、实盘录入、差异预览/过账、取消解冻和对应详情链接。所有改变实际流程状态的操作使用服务端保存并绑定完整参数的意图和签名确认。数量、盘盈成本与日期必须来自用户；不自动把账面数视为实盘数。已过账纠错必须有明确补偿语义，不能删除原流水。

## 冻结创建的锁内预览与绑定执行（Core 基础）

创建逻辑抽取为共享的持锁计划，供 `creation_preview` 和 `create_guarded` 使用。预览回滚只读事务，不创建盘点、编号、审批或冻结记录；返回完整创建命令、仓库业务单元、每个 SKU 的品牌、库存数量/预留/隔离/价值/均价、最后流水和库存版本，以及冻结到过账或取消的影响说明。受控创建必须逐项匹配服务端获批快照，状态变化返回 StalePreview。新操作使用独立的幂等操作名，摘要绑定命令与获批快照；普通浏览器创建保留原摘要与行为。

持有法人、仓库、商品与库存锁后核对授权版本，并在同一个数据库连接内重新读取完整身份、角色、权限和范围。不能只依赖授权版本号，因为用户/角色停用未必递增该版本。`PgStore::snapshot` 增加内部连接复用入口，IAM 时效读取使用当前时钟；受控创建不会持有唯一连接后再从池中申请另一连接。创建的幂等快照回读也复用事务连接。

隔离数据库 `inventory_count_creation_complete` 的完整 B2 流程通过：重复预览不增加盘点/事件/流水；观察实际库存行锁等待后改变库存版本、撤销品牌、停用角色或停用用户，执行均拒绝且没有新增盘点记录；变更备注也使预览失效。重新预览后创建成功，重复确认幂等，同键篡改快照拒绝，重叠冻结预览拒绝，取消后可再预览。单连接池下创建及重试通过。日志 `/tmp/business-count-creation-complete.log`。

## 实盘录入、差异过账与取消的 Core 绑定执行

新增封闭的 InventoryCountOperation（Submit/Post/Cancel）及共用持锁预览。快照包含完整命令、盘点版本/状态、当前与冻结业务单元/品牌、逐行当前库存/价值/预留/隔离/均价/最后流水/版本、已录实盘值和差异影响。取锁后使用同一连接重新读取完整权限；受控执行重算并比较全部快照，不能只用盘点头版本代替逐行核对。

录入保存所有实测行并保留冻结，不立即改变余额；过账写差异并释放冻结；取消要求非空原因，保存原因并释放冻结，不改变数量或成本。取消预览绑定当前余额，但允许取消已出现账面快照差异的盘点，以免把解冻也困在差异校验中。普通浏览器入口保留原输入和摘要，受控操作单独绑定单据 ID、输入和获批快照。取消事件/审计补记原因。

过账和预览共用差异计算，数量不允许低于预留与隔离之和；缺成本、负成本、负库存价值和十进制计算溢出拒绝。清零结转完整库存价值，零差异保留原均价。原账面快照比较补齐均价检查，避免数量/价值相同却使用已变化的成本。
