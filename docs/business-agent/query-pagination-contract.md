# BizOS 批量查询范围、排序与分页契约

本契约统一中文 BizOS 批量查询回复。目标是让“最近五笔”“前十项”“全部匹配”和“唯一匹配”等说法与工具实际返回的数据范围、顺序和分页状态一致。

## 范围与数据时点

- 范围只来自用户明确条件和工具返回的 `scopeSummary`。可以概括为“当前授权范围”，不能列举、推断或统计被授权过滤掉的对象。
- 顶层 `asOf` 和嵌套 `dataAsOf` 按日期时间契约显示为“数据时点”。工具未提供时不得用回复时间代替。
- 币种、期间、法人主体、业务单元、仓库、往来方、状态等筛选条件应在会影响理解时简洁说明，不重复内部 UUID。
- 工具状态为 `partial` 时明确标注“部分结果”，并展示服务端警告或缺失范围；不能把部分结果称为完整清单。

## 排序

- 保持工具返回顺序，不能自行改排，也不能按格式化后的日期、金额、编号或状态重新排序。
- 只有工具明确返回或工具契约明确规定排序字段和方向时，才能说“按订单日期降序”“按创建时间倒序”等。
- 工具没有提供排序依据时明确写“排序依据未提供”。此时可以说“按工具返回顺序列出前 5 条”，不能说“最近 5 条”“最新 5 条”或“金额最高 5 条”。
- 排序相同值的稳定次序也必须来自服务端；不能自行假设 UUID、编号或更新时间是次级排序键。

## 分页权威字段

- 标准游标结果使用 `pagination.hasMore` 和 `nextCursor`。
- offset 适配结果使用 `summary.nextOffset` 和 `pagination.hasMore`；来源页在委托范围过滤后可能为空，但只要 hasMore 为 true 就仍需继续。
- 库存盘点预览使用 `previewPagination.nextOffset`、`previewPagination.hasMore` 和服务端总行数；详情后续页必须携带首页版本，版本变化时从头读取。
- 费用调整搜索使用服务端 `nextCursor` 作为下一次 `afterId`；费用详情的 `nextCursor` 是 offset。字段同名不表示语义相同，必须遵循具体工具说明。
- 后续调用原样传递服务器返回的游标或 offset。不要向用户展示不透明游标，不自行生成、递增、解析或修复它。

不能仅因返回条数等于 limit 判断还有下一页，也不能因为少于 limit 就断言已经结束。只有权威分页字段能决定是否续页。

## 完整性措辞

- 当前页有 5 条且 `hasMore=true`：写“当前页 5 条，仍有更多结果”。
- 已读取所有页、状态完整且没有警告：可以写“共 5 条”。
- 服务端明确返回总数：可以使用该总数，并区分“共 37 条，当前显示 5 条”。
- 没有分页字段：写“当前返回 5 条，完整性未由工具说明”。
- `status=partial` 或存在影响完整性的警告：写“当前返回 5 条，为部分结果”，并说明已验证原因。

不能推断总数。`items.length`、页数、下一页游标是否存在、客户端显示数量或历史查询数量均不能替代服务端总数。

## 何时继续翻页

- 用户只要求前 N 条：取得 N 条后可以停止；如仍有下一页，必须说明结果被用户请求的数量截断且仍有更多。
- 用户要求全部结果、总数、完整清单或跨页汇总：读取全部分页后才能回答。任何页面失败或快照变化时，说明未完成，不用已读页冒充全部。
- 判断名称、编号或资源是否唯一匹配，以及为写入解析唯一对象：必须读取全部分页。单页只有一条、当前页只有一条或过滤后空页都不能建立唯一性。
- 用户要“最近 N 条”但工具没有声明排序：可以返回前 N 条，同时明确排序依据未提供；不能把它们验证为最近 N 条。

跨页时保持初始筛选条件不变。若版本、数据时点、排序或查询范围发生变化，应停止合并并重新开始；除非工具明确提供冻结快照保证，否则不能声称多页来自同一事务快照。
