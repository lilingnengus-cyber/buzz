# BizOS 名称查找与歧义解析契约

本契约统一中文 BizOS 依据名称或编号查找客户、供应商、SKU、仓库、业务单据和其他业务对象时的回复。解析结论必须来自当前授权工具的完整结果；名称相似、历史对话、默认配置和内部 ID 都不能替代用户选择。

## 三种解析结果

| 结果 | 成立条件 | 用户回复与后续动作 |
| --- | --- | --- |
| 零匹配 | `status=ok`、结果完整、没有完整性警告，且没有候选 | “当前范围内没有匹配项”，说明已验证查询范围；不说全局不存在 |
| 唯一匹配 | 读取全部分页后仅有一个候选，`pagination.hasMore=false`，状态完整且无影响完整性的 warning | 说明已确定的业务编号／代码和名称；在写入场景仍需确认其他必填业务选择 |
| 多个匹配 | 完整结果中有两个或以上候选 | “请从以下候选中选择”，展示候选的业务编号／代码、名称和必要区分信息，等待用户明确选择 |

精确资源读取返回 `not_found_or_forbidden` 时仅回复“未找到或无权访问”。它不属于零匹配，不能据此判断资源是否存在。

## 完整性要求

- 判断零匹配或唯一匹配前必须读取全部分页。`pagination.hasMore=true` 时继续读取下一页；当前页为空也不能停止。
- 分页字段缺失、`status=partial`、完整性 warning、跨页快照变化或页读取失败时，说明“部分结果”或“完整性未由工具说明”，不能建立唯一匹配，也不要要求用户选择。
- 委托过滤可能使当前页为空或隐藏候选。回复只描述当前授权范围，不披露被过滤对象、数量、游标或内部权限策略。
- 用户只要求候选列表时，可以列出当前已验证候选并说明完整性；列表不等于用户已经选定对象。

## 多个匹配的展示与选择

多个匹配时使用一句“请从以下候选中选择”，然后列出每个候选的：

- 业务编号或主数据代码；
- 名称；
- 当前工具已验证且有助于区分的字段，例如法人主体、业务单元、状态、仓库或计量单位。

不要求用户提供内部 UUID，也不展示内部 UUID。用户可以回复业务编号／代码，或能够唯一指向候选的清晰名称。不能自动选择第一条，不能因名称相似、历史上下文、更新时间、排序、默认法人主体、默认仓库或默认商品而缩小候选。

如果候选缺少业务编号／代码，使用经验证的名称和必要区分字段；仍无法让用户明确选择时，集中询问一个能消除歧义的业务字段。

## 写入前边界

写入前，名称解析必须产生用户明确选择的唯一对象。助手只能复用本次授权工具返回的内部 ID；不能在多匹配、部分结果或未完成分页时调用写入工具、填入内部 ID、制作确认预览或把候选当成已确认选择。

唯一对象解析成功也不会补齐数量、金额、日期、币种、仓库、单位、行项目或其他业务必填项。缺失字段仍要一次性说明并等待用户提供或确认。

## 示例

零匹配：

> 当前授权范围内，客户名称“杭州示例客户”没有匹配项。数据时点：2026-09-25 09:00（UTC+8）。

多个匹配：

> 找到多个“杭州客户”匹配项，请从以下候选中选择：
>
> - CUS_HZ_001｜杭州客户｜侠客宇宙｜启用
> - CUS_HZ_002｜杭州客户｜杭州分部｜启用

部分结果：

> 当前结果为部分结果，暂不能判断“杭州客户”是否唯一匹配；待完整结果可用后再选择。

自动契约测试位于 `crates/buzz-acp/src/business_agent/tests.rs`，固定零匹配、唯一匹配、多个匹配、分页完整性、UUID 隐藏与写入前用户选择边界。
